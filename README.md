# Local job bot

The local control UI runs in Docker and binds to `127.0.0.1` by default. Start it with `docker compose up -d --build web`; setup and optional network binding are documented in [DOCKER.md](DOCKER.md). Persistent app state and private app secrets live in ignored host directories mounted into the container.

The UI now has owner setup, sign-in, member accounts, a comprehensive candidate profile form, saved settings, a shared public job pool, and a durable private queue for each account. Leave profile answers blank when unknown; repeatable entries have “Add another” controls. On the Profile page, upload PDF, DOCX, or text resumes as a primary resume or targeted to a role or region; each uploaded file can be labeled, downloaded, and approved separately. Pasted text remains available for the primary resume. The old text-only role-specific editor is hidden, while previously saved entries remain visible. The app extracts readable text and suggests explicit header contact details, a clearly labeled summary, and listed skills for review; it does not infer qualifications. Scanned PDFs may need pasted text. Each UI account gets a separate SQLite ledger and queue; candidate profiles and uploaded resumes are encrypted with a key stored outside the database. The existing Gmail and Google Sheets adapters still use the original owner's single-user configuration and are not connected to member accounts.

Job preferences in the profile are flexible ranking hints. Add search phrases such as “nursing,” “HPC engineering intern,” or “SWE intern” in **Settings → Job searches**. The always-on discovery worker searches the public web through the private SearXNG container; Adzuna is an optional job-specific provider. No search API key is required. **Scrape jobs** accepts target titles and an optional permitted employer careers URL. In **Settings → Scrape jobs**, each entry has its own target for new, unique queue items (1–200 per cycle) and wakeup interval (1 minute to 24 hours, default 6 hours). The search scans more result pages while needed to reach that target, including after duplicate URLs are skipped. It reports the requested target and actual count in its logs. A source can finish below target if it runs out of valid results or reaches provider request limits. Use **Run now** on a row to request an immediate scan of that source; provider request caps still apply. Saved phrases under **Job searches** continue on their separate six-hour cadence. Discovery uses local `gemma4:e2b` to classify each SearXNG result as one job, a collection page, other, or uncertain before it can enter the queue. The model uses only the visible result title and snippet for role and employer facts; an unknown employer remains blank. If the model is unavailable or returns invalid output, that search is retried later without queueing raw results. A public collection result may instead seed a bounded two-level, same-host crawl; only structured `JobPosting` records from pages allowed by robots.txt become jobs. An optional configured careers URL uses the same structured-data approach. The exact full individual job URL is the listing identifier and duplicate key. The date limit applies only where a posting date is available. Every new listing is scored by the local text-only EmbeddingGemma 2 service using approved preferences and saved search phrases. The separate applier uses local `gemma4:e4b` to interpret application form controls using only relevant, approved candidate facts. Neither role receives credentials or secrets; required unknown answers, legal attestations, and verification challenges go to a person. See [DOCKER.md](DOCKER.md) for model setup and worker controls.

The discovery worker is a persistent Docker service with a one-minute scheduler tick and automatic restart. Each **Scrape jobs** entry has its own target for new queue items (up to 200) and wakeup interval. It scans more SearXNG pages until the target is reached or the query results and provider budget run out; the actual count and target are logged per run. The worker reads explicitly configured employer pages and searches the web according to saved job titles. Local `gemma4:e2b` classifies SearXNG search results, and each discovered listing is scored immediately with the local, text-only 270M-parameter EmbeddingGemma 2 model using saved searches and approved soft preferences. The similarity score is advisory; it is not a probability or a qualifications check. Public jobs from SearXNG and permitted pages or feeds are deduplicated by exact URL in the shared pool, then linked to the discovering user's private queue. Adzuna results remain private. Other accounts can add a pooled job to their own queue; they do not share application status or profile data. **Apply queue** lets you add a job directly by its full URL; manual entries stay private unless shared using the checkbox. For employer pages and selected collection results, discovery checks robots.txt, parses schema.org JobPosting data, and follows a bounded number of same-host job links. Collection pages are crawl seeds, never application targets. Known old collection entries have been skipped in the private queue and hidden from the shared pool while their exact URLs and audit history remain saved. The separate always-on applier uses local `gemma4:e4b` to interpret application form labels and controls, then maps them to the approved profile facts and primary resume relevant to that job. It fills exact approved facts; a model-written narrative sends the job to review until the user supplies an approved answer. The applier can follow one explicit same-host Apply link after a separate public URL and robots.txt check, while the original listing URL remains the ledger key. It checks the daily limit before submitting (`-1` means unlimited), and requires an employer confirmation page before marking a job applied. On CAPTCHA or sign-in verification, the applier keeps that user's application browser open for a human. A direct **Open browser view** button appears at the top of the owning user's **Apply queue** and on the job's history page; the temporary password appears only on that history page. Only one human handoff is active at a time, and VNC is bound to `127.0.0.1`. Missing or unknown required answers, legal attestations, sensitive disclosures, ambiguous forms, site blocks, or uncertain outcomes go to review. Each private job has a history page showing its saved full URLs and recent state changes. See [DOCKER.md](DOCKER.md) for model setup, controls, and safety boundaries and [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) for the remaining roadmap.

Gmail sync is disabled by default. See [GMAIL_SETUP.md](GMAIL_SETUP.md) for OAuth setup and [DOCKER.md](DOCKER.md) for starting the optional worker container.
